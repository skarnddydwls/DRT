# 일배차 시간표 시뮬레이터

센터 프로젝트 루트의 `일배차_시뮬레이션.cmd`를 더블클릭합니다.
Python 3.10 이상과 PostgreSQL의 `psql.exe`가 필요합니다. Python 외부 패키지는 필요 없습니다.

## 실행 메뉴

1. 예약구간 모드: **1 = 실제 예약 기준(무조건 운행 OFF)**, **2 = 무조건 운행 ON**.
2. 차량: **Enter 또는 `ALL`은 1·2호차 동시 실행(기본)**입니다. `1`은 1호차만, `2`는 2호차만 실행합니다. 전체 차량 ID를 직접 입력할 수도 있습니다.
3. 배속: 기본 `1`은 실제 시각, `10`은 실제 1초에 시간표 10초가 흐릅니다.
4. 시작 시각: Enter는 현재 한국 시각. 아침부터 재현하려면 `07:00`처럼 입력합니다.
선택을 마치면 시간표를 점검한 뒤 위치 기록을 시작합니다. DB 기록 없이 점검만 하려면 아래 `-Check` 명령을 사용합니다.

실행 창을 유지하고 종료할 때 Ctrl+C를 누릅니다. 기존 단순 노선 시뮬레이터와 동일 차량 토큰을 공유하므로, 이 PC에서 이전 시뮬레이터는 다음 주기에 중지됩니다. 다른 PC에서 보내는 좌표까지 중지시키지는 않습니다.

동시 실행은 한 프로세스에서 같은 시작시각·배속·시뮬레이션 시계를 사용합니다. 각 차량은 자기 일배차·예약·현재 노선을 따로 관리합니다. 한 차량의 시간표 오류/운행 종료/실제 기사 운행 시작이 다른 차량을 중단시키지 않습니다. 오류가 있는 차량은 ID와 사유를 표시하고 제외하며, 남은 차량은 계속 실행합니다. 전체 종료는 Ctrl+C입니다.

## 시간표와 이동

- `DRT_DISPATCH_DAY`의 해당 일자·차량에 배정된 모든 노선을 시간순으로 연결합니다. 차량 미배정 배차는 임의로 가져오지 않습니다.
- `ALGH_DTM`은 정류장별 고정 도착시각이며 `DISPATCH_SEQ`로 노선편집의 `POINT_SEQ`와 매칭합니다. 반복 정류장도 순번을 구분합니다.
- 한국 시각의 해당 날짜에 맞는 계절·요일 노드 구성을 `fn_route_nodes_for_date`에서 읽습니다.
- 등록된 노드 선을 따라 거리에 비례해서 이동합니다. 기본 주행속도는 25km/h이며, 일찍 도착하면 정류장에서 대기합니다. 배차 간격이 짧으면 고정 시각을 맞추도록 시뮬레이션 속도가 증가합니다. 물리적으로 가능한 운행시간 검증 도구는 아닙니다.
- 앞·중간·끝의 예약구간을 생략해도 남은 정류장 도착시각은 변경하지 않습니다. 전체가 미예약 구간인 노선은 운행하지 않습니다. 이전에 운행한 노선이 있으면 마지막 운행 기준으로 대기/다음 유효 노선까지의 이동 위치를 유지합니다. 처음부터 모두 미예약이면 위치를 발행하지 않습니다.
- 노선 사이에는 등록된 노드망을 따라 다음 노선 기점으로 이동합니다. 별도의 회송 시간표는 없으므로 이전 종점~다음 기점 사이 시간을 사용합니다.
- 우회는 전체 노선편집 좌표망의 최단 연결을 이용합니다. 도로 길찾기 API가 아니며 도로 일방통행·교통상황은 반영하지 않습니다. 생략할 정류장을 통과하는 경로는 제외하고, 연결 경로가 없으면 실패합니다. 임의의 직선 우회는 만들지 않습니다.
- 배차표/노드 구성은 시작 시 읽습니다. 편집했다면 재실행해야 합니다.

## 실제 예약 판정

- `DRT_VEHICLE_USE_LOG.RSV_STATUS='WAIT'`인 예약만 사용합니다. 취소·완료 예약은 제외합니다.
- 환승 예약은 `DRT_VEHICLE_CALL_LEG`의 일자·차량·노선·시작/종료 순번을 이용합니다. leg가 없는 기존 예약만 호출 로그와 일배차를 매칭합니다.
- 연속된 `EXT_DISPATCH_DIV` 코드를 예약구간으로 보고, 유효한 예약의 승·하차/통과 범위가 해당 구간과 겹치면 운행합니다. 비어 있지 않은 코드 전체가 대상입니다.
- 예약은 실제 5초마다 다시 읽습니다. 직전 고정 정류장을 출발하기 전 변경은 반영하고, 이미 진입한 선택구간은 운행 여부를 고정하여 중간에 경로가 바뀌지 않게 합니다. 뒤늦게 접수된 예약 때문에 지나간 구간으로 돌아가지는 않습니다.
- 실행 중 모드 변경은 Ctrl+C 후 다시 실행하여 선택합니다.

## 기록과 제한

위치는 실제 전송 시각의 `DRT_OPER_LOG`에 저장합니다(`GPS_X=경도`, `GPS_Y=위도`). 배속 시각은 콘솔에 표시됩니다. 센터 모니터링에는 기존 자동 갱신으로 표시되며, 시뮬레이션 로그가 운행기록에도 남습니다. 배차·예약 상태나 기사 운행 상태는 변경하지 않습니다.

실제 기사 운행이 열려 있거나 `oper_yn=N`으로 숨겨진 차량은 실행을 막습니다. 실제 운행과 혼용하지 않을 차량을 선택합니다. 모니터링이 연결한 DB와 시뮬레이터의 datasource DB가 같아야 합니다.

시간 역전·중복 배차·노선 중첩·누락 좌표는 오류로 안내합니다. **2026-11-05 점검 시 2호차_7에는 도착시각 역전이 있어, 해당 일배차를 수정하기 전에는 2호차 실행이 차단됩니다. 동시 실행 시에도 정상인 1호차는 계속 실행합니다.** 배차 시각을 자동 수정하지 않습니다.

서버 PC에서는 센터 프로젝트의 CMD 및 scripts 폴더를 함께 복사/pull합니다. datasource 위치는 아래처럼 지정할 수 있습니다. 비밀번호는 CMD에 넣지 않고 기존 백엔드 XML에서 읽습니다.

```powershell
# 실제 예약 기준 / 읽기 전용 점검
.\scripts\dispatch-simulator.ps1 -Check -ReserveMode actual -VehicleId VH00000001

# 1·2호차 동시 실행 / 같은 시각·10배속 (실제 운행 로그를 기록함)
.\scripts\dispatch-simulator.ps1 -VehicleId ALL -ReserveMode always -Speed 10 -StartTime '07:00'

# 무조건 운행 ON / 10배속 / 07:00부터 (실제 운행 로그를 기록함)
.\scripts\dispatch-simulator.ps1 -ReserveMode always -Speed 10 -StartTime '07:00'

# 서버 datasource 지정
.\scripts\dispatch-simulator.ps1 -Check -BackendRoot 'C:\DRT\eGovFrameDev_DRT\workspace-egov\drt'

# Python 직접 실행: 단일 노선 읽기 전용 점검
python scripts/dispatch-simulator.py --vehicle VH00000001 --route RT00000006 --reserve actual --check
```

## 검증

오프라인 동작 테스트:

```powershell
python -m unittest discover -s tests -p test_dispatch_simulator.py -v
```

`--rollback-probe`는 위치 INSERT를 트랜잭션 안에서 실행하고 ROLLBACK합니다. `--check`는 SELECT만 수행하며 운행 로그를 남기지 않습니다.
